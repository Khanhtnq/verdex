# Verdex production audit, 12 October 2026

A check of the live site after holders reported that Pools, Index and the baskets did not load. Written by the
engineering agent that built the site. This is not a third-party audit; it is what was found, what was changed
and what was checked afterwards against production (useverdex.xyz and both chains).

## What was wrong

- **Cause.** The public API (box 2 of phase 3) added a route that answered every path under `/api`. The site
  reads its own data files from that folder too, so `/api/assets.json` (the list of every stock) and the basket
  lists returned 404.
- **Effect.** Every page that needs the list of stocks waited forever: Pools, Index, the baskets, Vaults and the
  composers of the without-you pages. Trading through a contract was never affected, because no contract reads
  that file, and no contract was touched.
- **Fix.** `server.mjs` now answers only real API endpoints; any other `/api` path with a file extension is served
  as a file. The API endpoints are unchanged.

## What was checked afterwards

Every contract: code onchain, an exact match on Sourcify, and who owns or administers it. Every API endpoint:
status and size. Every public page: loaded in a browser for 18 seconds, with any error status from useverdex.xyz
or any script error counted as a failure. Result: **0 failures**.
